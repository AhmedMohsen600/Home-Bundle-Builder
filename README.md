# Home Bundle Builder

Open-source React implementation of a guided home security bundle builder. The
app lets shoppers configure a Wyze-style protection system by choosing cameras,
a monitoring plan, sensors, and add-ons while a sticky review panel keeps totals,
savings, variant quantities, and checkout actions in view.

## Live Demo

Production deployment:
https://home-bundle-builder.vercel.app

## Features

- Four-step bundle flow for cameras, plans, sensors, and extra protection.
- Product catalog powered by structured JSON data.
- Variant-aware selections, including independent quantities per color.
- Live review panel grouped by product category.
- Automatic pricing, compare-at totals, and savings calculations.
- Save-for-later support with `localStorage` restoration.
- Responsive Vite, React, TypeScript, and Tailwind CSS implementation.
- Vitest coverage for components, state utilities, calculations, and design
  tokens.

    bundle-builder/
      components/   # Product cards, step sections, review panel, controls
      constants/    # Shared bundle constants and labels
      data/         # Catalog content and default selections

The main experience is exported from

## How the Code Works

The application is organized around one feature module:
`src/features/bundle-builder`. That module owns the product data, TypeScript
domain types, state logic, UI components, persistence, and tests for the bundle
builder.

### App Entry

`src/App.tsx` renders the `BundleBuilder` feature:

```tsx
import { BundleBuilder } from './features/bundle-builder'

function App() {
  return <BundleBuilder />
}
```

`BundleBuilder.tsx` is the top-level screen component. It loads the default
catalog from `data/catalog.json`, connects it to `useBundleBuilder`, renders the
step accordion on the left, and renders the review panel on the right.

### Data-Driven Catalog

All products and steps are defined in
`src/features/bundle-builder/data/catalog.json`.

The catalog controls:

- Step order and titles.
- Product names, descriptions, categories, images, prices, and badges.
- Color variants and variant-specific images.
- Default selected products through `initialSelection`.
- Required products, such as the Wyze Sense Hub.

Because the UI reads from this catalog, adding or editing products usually means
changing JSON instead of changing React components.

### Domain Types

`src/features/bundle-builder/types/bundle.types.ts` describes the shape of the
bundle domain:

- `BundleCatalog` contains steps and the initial selection.
- `BundleStep` contains the products shown in one accordion section.
- `BundleProduct` contains pricing, imagery, metadata, and optional variants.
- `BundleState` tracks the active step, active variant per product, and selected
  quantities.
- `ReviewLine` and `BundleTotals` describe the data shown in the review panel.

The central state shape is:

```ts
interface BundleState {
  activeStepId: string
  activeVariantByProduct: Record<string, string>
  quantities: Record<string, number>
}
```

Variant quantities use a stable line key generated by
`createLineKey(productId, variantId)`. For example, `wyze-cam-v4:white` and
`wyze-cam-v4:black` are treated as separate review lines.

### State Management

`src/features/bundle-builder/hooks/useBundleBuilder.ts` is the main feature
controller. It owns the React state and exposes actions to the UI:

- Open or close a step.
- Move to the next step.
- Change a product variant.
- Increase, decrease, or clear quantities.
- Save the current bundle for later.
- Trigger the prototype checkout message.

The hook keeps rendering components simple. Components receive the current
selection state and call callback props; they do not need to know how totals,
storage, or catalog hydration work.

Pure state transitions live in
`src/features/bundle-builder/utils/bundleState.ts`. This file creates the
initial state, updates active steps and variants, normalizes quantities, removes
zero-quantity lines, serializes state for storage, and safely hydrates stored
state against the current catalog.

### Selection Logic

`src/features/bundle-builder/utils/bundleSelection.ts` converts raw state into
the product-level information components need:

- Which variant is active for a product.
- The quantity for the active product or variant.
- Whether a product should appear selected.
- How many products are selected in a step.

This keeps selection rules consistent across product cards, step headers, and
review totals.

### Pricing and Review Panel

`src/features/bundle-builder/utils/bundleCalculations.ts` turns the selected
state into review data.

It groups selected products by category, creates one review line per selected
product or variant, calculates the current bundle price, calculates the
compare-at total, and derives total savings.

`src/features/bundle-builder/components/ReviewPanel.tsx` renders that output as
the sticky summary card. It displays selected cameras, plan, sensors,
accessories, free shipping, savings, checkout, and save-for-later actions.

### Product and Step UI

`StepSection.tsx` renders each accordion section. It shows the current selected
count, opens the active step, maps catalog products into `ProductCard`
components, and exposes the next-step action.

`ProductCard.tsx` renders one product. It handles:

- Product image and fallback icon.
- Title, description, badge, and Learn More link.
- Variant selector when variants exist.
- Quantity stepper.
- Current price, compare-at price, and billing label.
- Required product minimum quantity.

Small UI pieces such as `QuantityStepper`, `VariantSelector`, `PriceBlock`, and
`ReviewLineItem` are split into focused components so they can be tested and
changed independently.

### Persistence

`src/features/bundle-builder/hooks/useBundlePersistence.ts` saves the current
configuration in `localStorage` under this key:

```ts
home-bundle-builder:configuration
```

When the app loads, saved state is parsed and validated against the current
catalog. Invalid, deleted, or outdated product keys are ignored so stale browser
storage does not break the UI.

### Styling

The app uses Tailwind CSS through `@tailwindcss/vite`. Most styling is local to
the component that owns the markup, while shared visual tokens live in
`src/index.css`.

The layout uses a responsive two-column structure on large screens and a stacked
layout on smaller screens. The review panel becomes sticky on desktop so totals
remain visible while the shopper moves through the steps.

### Tests

The project uses Vitest and Testing Library. Tests cover:

- Product card behavior.
- Quantity controls.
- Variant selection.
- Review line rendering.
- Review panel totals.
- Bundle state utilities.
- Bundle architecture expectations.
- Design tokens.

Run the full suite with:

```bash

```

## Catalog Data

Product and step content lives in
`src/features/bundle-builder/data/catalog.json`. Updating this file changes the
products, variants, prices, badges, step labels, and initial bundle selection
without touching the UI components.
